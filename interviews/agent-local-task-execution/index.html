Cola 本地任务执行 Agent

📋 AI Agent 工程化全栈面试题 ⏱️ 预计用时 1~3 天 🏢 ColaOS

背景

Cola 是一个桌面 AI Agent。用户真正需要的不是问答，而是把一句自然语言变成一段可靠的本地任务执行过程：理解目标、拆解步骤、调用工具、遇到错误能恢复、必要时请求确认，并把过程清楚地展示给用户。

请实现一个小型的本地任务执行 Agent。重点不在模型多聪明，而在 Agent Runtime、工具协议、任务状态、风险控制和可观测性。

场景示例

用户说："帮我检查这个前端项目为什么测试失败，如果是简单问题就修掉，并给我一份结果摘要。"

→ Agent 生成任务计划，列出会读取哪些文件、运行哪些命令

→ Agent 调用工具查看目录、读取配置、运行测试

→ 测试失败后，Agent 定位到可疑文件并提出补丁

→ 涉及文件修改前，Agent 标记风险并请求确认或进入模拟确认流程

→ Agent 应用补丁、重新运行测试，最后输出摘要和完整 trace

时间安排

Day 1
方案设计 + Fixture 准备
Day 2-3
技术实现 + Demo 讲解

任务一：方案设计

Day 1 输出一份简短设计说明，覆盖以下内容：

  • Agent 执行循环：如何从用户目标生成计划、调用工具、观察结果、继续决策、结束任务
  • 任务状态模型：如何表达 pending / running / waiting_approval / failed / completed 等状态
  • 工具协议：工具输入、输出、错误、风险等级如何结构化
  • 安全边界：哪些操作需要确认，如何阻止危险命令或越权文件访问
  • 可恢复性：任务执行到一半失败或中断，如何从 checkpoint 恢复

任务二：技术实现

Day 2-3 实现一个可运行 Demo。CLI、Web UI 或本地 API 都可以，Web UI 加分但不强制。

必须实现的工具

工具可以操作一个你自己准备的 fixture 项目，也可以使用 mock 文件系统。至少包含：

list_files(path)
read_file(path)
run_command(command, cwd)
propose_patch(file_path, diff)
apply_patch(patch_id)
run_tests(target)
write_task_report(content)

必须实现的 Agent 能力

  1. 真实执行循环：不能只做一次 LLM 调用后直接输出结果，需要有 plan → tool call → observe → next step → final。
  2. 工具错误处理：命令失败、文件不存在、测试超时、补丁冲突时要有明确处理路径。
  3. 风险控制：读文件、运行测试、修改文件、删除文件应有不同风险等级；高风险操作必须被拦截或确认。
  4. 任务进度展示：用户能看到当前步骤、已完成步骤、失败原因和下一步。
  5. Trace Log：输出完整执行记录，包含每次工具调用的参数、结果、耗时、错误和 Agent 决策。
  6. 最终摘要：说明做了什么、改了什么、验证结果、仍有哪些不确定性。

Fixture 要求

请准备一个小型项目作为 Agent 的任务环境，里面至少包含一个会失败的测试或 lint 问题。问题不需要复杂，但要能体现 Agent 的定位、修改和验证流程。

提示：可以使用真实 LLM，也可以 mock LLM 响应。我们重点看 Agent 工程设计，不要求模型本身完成复杂推理。

任务三：设计说明

交付时附带 回答以下五个问题：

  1. 你的 Agent 状态机核心数据结构长什么样？
  2. 工具调用结果如何影响下一步决策？
  3. 如何判断一个操作需要用户确认？
  4. 如果任务运行 30 分钟后进程崩溃，如何恢复？
  5. 如果未来要接入真实桌面操作工具，你的工具协议需要做哪些扩展？

验收用例

请至少保证以下类型的指令能稳定运行：

用例 1："帮我检查这个项目为什么测试失败，如果是简单问题就修掉。"

用例 2："只读模式检查项目健康状况，不要修改任何文件。"

用例 3："运行测试并生成报告；如果命令失败，告诉我失败在哪一步。"

用例 4："尝试修复 lint 问题，但修改前必须先让我确认。"

评估维度

维度权重看什么
Agent Runtime30%执行循环、状态机、步骤推进、结束条件是否清楚
工具协议与安全边界25%工具抽象、风险等级、确认机制、错误处理是否扎实
可观测性与恢复能力20%trace、进度展示、checkpoint、失败恢复是否可用于真实排障
工程质量15%代码结构、类型约束、测试、README、可维护性
产品体验10%任务过程是否让用户安心，最终摘要是否清楚、有用、不过度承诺

交付物清单

  • 可运行的代码仓库或压缩包
  • fixture 项目或 mock 文件系统数据
  • README：启动方式、测试方式、Demo 指令、架构说明
  • Agent trace 示例文件，例如 trace.json
  • 5 到 10 分钟 Demo 讲解，重点讲执行循环、工具协议、安全边界和恢复策略

注意事项

  • 可以使用 AI Coding 工具，但需要能解释核心实现。
  • 不要求接入真实系统终端；可以在受控 fixture 或 mock 环境中模拟。
  • 不要实现危险操作，例如真实删除用户文件、访问系统敏感路径、执行不可控脚本。
  • 请优先保证核心流程完整、可运行、可解释，再考虑额外功能。
